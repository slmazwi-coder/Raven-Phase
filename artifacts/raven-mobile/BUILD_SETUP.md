# Raven — Build Setup Guide

## Prerequisites

| Requirement | Notes |
|---|---|
| Expo / EAS account | Sign up at [expo.dev](https://expo.dev) |
| EAS CLI | `npm install -g eas-cli` |
| Apple Developer account | Required for iOS / TestFlight ($99/yr at [developer.apple.com](https://developer.apple.com)) — not yet required for Android |

---

## Step 1 — Link your EAS account

```bash
eas login
eas init --id <your-project-id>   # creates an EAS project and writes the projectId to app.json
```

After `eas init`, update `app.json` → `expo.extra.eas.projectId` with the value it prints.

---

## Step 2 — Android internal build (no Apple account needed)

```bash
eas build --profile preview --platform android
```

- EAS generates a managed keystore automatically (no signing setup needed for internal builds).
- When complete, scan the QR code or download the `.apk` from [expo.dev](https://expo.dev/accounts) and install it directly on your Android device.
- **Confirm it installs and opens** before moving to iOS.

---

## Step 3 — iOS TestFlight (requires Apple Developer account)

### 3a — Apple Developer account setup

1. Enroll at [developer.apple.com/programs](https://developer.apple.com/programs/) ($99/yr).
2. Wait for enrollment approval (usually same-day to 48 hrs).

### 3b — Run the iOS build

```bash
eas build --profile production --platform ios
```

EAS will:
- Generate a distribution certificate and provisioning profile automatically (first run only).
- Build the `.ipa` in the cloud.
- Prompt you to log in to App Store Connect via the Apple ID associated with your Developer account.

### 3c — Submit to TestFlight

```bash
eas submit --platform ios --latest
```

Or configure auto-submit in `eas.json` → `submit.production.ios`.

### 3d — Invite testers

In App Store Connect → TestFlight → your build → add testers (internal or external).  
External testers require Apple review (usually < 24 hrs for a messaging app).

## Environment variables

| Variable | Where set | Purpose |
|---|---|---|
| `EXPO_PUBLIC_DOMAIN` | Injected by dev script from `$REPLIT_DEV_DOMAIN` | API base URL for dev |
| `DATABASE_URL` | Replit secret | Backend PostgreSQL connection |
| `SESSION_SECRET` | Replit secret | JWT signing key |
| `TWILIO_*` | Replit secrets | OTP SMS delivery |

For **production builds**, set `EXPO_PUBLIC_DOMAIN` to your deployed backend domain (e.g. `raven.yourdomain.com`) in `eas.json` or via `eas env:create`.

---

## QR code testing (Expo Go — no build needed)

For rapid iteration on a physical device without a full EAS build:

1. Install **Expo Go** from the App Store / Play Store.
2. Open this Replit project and click the **QR code** icon in the URL bar menu.
3. Scan the QR code with Expo Go.

> **Note:** WebSocket real-time messaging requires the backend to be reachable from your device. On a local device via Expo Go, the Replit dev domain (`$REPLIT_DEV_DOMAIN`) is publicly accessible, so this works out of the box.

---

## Certificates generated by EAS (reference)

EAS auto-generates and manages all certificates. For your records, after running builds you can view them at:

- [expo.dev → your project → Credentials](https://expo.dev)
- iOS: Distribution Certificate + Provisioning Profile (stored in your Apple account)
- Android: Upload Keystore (stored in EAS — back up via `eas credentials`)

---

## Repeating a build

Subsequent builds simply re-run `eas build`. EAS reuses existing credentials unless you explicitly reset them with `eas credentials`.
